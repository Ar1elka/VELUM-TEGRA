## 2. Известные проблемы

### 2.1. Ключи Ed25519 — поддержаны (проверено на JVM и на телефоне)
Ed25519 разрешён как тип **пользовательского** ключа (`ssh-ed25519` в `userPublicKey`). Подпись выполняет BouncyCastle (`bcprov-jdk18on`) через классы `com.jcraft.jsch.bc.*`; на Android JSch выбирает их сам (версия Java меньше 15), провайдер JCA регистрировать не нужно. Ключи сервера и обмен ключами остались на ECDSA/RSA/DH, Curve25519 по-прежнему выключен.
- Проверено: вход по паролю-защищённому ключу Ed25519 (формат OpenSSH v1) на локальном SSH-сервере, и по пути JDK, и по пути BouncyCastle (его использует Android).
- **Проверено на телефоне** (Android 16, debug-сборка): импорт одноразового ключа Ed25519 без пароля, сохранение SSH-доступа, «Подключиться и проверить SSH» с чтением сведений о сервере. Работает на Debian 13 и на чистой Ubuntu 24.04.2 LTS (отпечаток хоста сверен вручную по консоли провайдера). На Debian в журнале сервера один вход этим ключом. На Android ниже 16 и с ключом, защищённым паролем, на устройстве не проверялось (парольная фраза проверена только на JVM).
- **Исправлена связанная ошибка.** Кнопка «Получить отпечаток с сервера» не ограничивала тип ключа хоста и возвращала `ssh-ed25519`, а вход разрешает только ECDSA/RSA, поэтому закреплённый отпечаток не совпал бы. Теперь проверка использует ту же политику (`SshHostKeyProbe.kt`, тест `probeObservesOnlyHostKeyTypesTheLoginPolicyAllows`).
- `SshKeyCapabilities.ed25519UserKeys` проверяет в рантайме, что нужные классы BouncyCastle загружены (на старых Android платформенная копия может их перекрывать). Если нет, при импорте показывается понятное сообщение.
- `UnsupportedPrivateKeyDetector` по-прежнему объясняет DSA и ключи с аппаратным токеном (`sk-…`).
- APK стал больше из-за BouncyCastle (jar около 8 МБ); размер release-сборки с сжатием ещё не измерен.

### 2.2. Приложение не умеет создавать подключения (inbound)
Подключения только читаются. VLESS создаётся руками в веб-панели 3x-ui (WebView).

### 2.3. Debian 11 и другие системы, снятые с поддержки
- `security.debian.org` отдаёт 404 на пакеты bullseye (пул переехал в `archive.debian.org`).
- `sqlite3` ставится только через запасной путь.
- **nginx не ставится.** Раньше приложение писало вводящее в заблуждение «нет сети к репозиториям»; теперь при неудаче оно читает `/etc/os-release` и для Debian 11 и старше или Ubuntu 18.04 и старше говорит, что система снята с поддержки (`SiteNginxInstallOutcome.UNSUPPORTED_OS`). Списки пакетов при этом не меняются.
- Решение — перевести строку security в `sources.list` на `archive.debian.org/debian-security`, но **только для снятых с поддержки версий** и только по явному подтверждению. Для Debian 12/13 и Ubuntu так делать нельзя: перестанут приходить обновления безопасности.

### 2.4. Тексты и UX
- После успешной сверки (шаг 2 восстановления) экран всё равно пишет «Наблюдения не разрешают восстановление или обновление».
- ~~Шаг 3 восстановления не говорит, что сверка действует 5 минут~~ — исправлено: отказ теперь это объясняет.
- ~~В режиме резервной копии статус пишет «Обновление не запускалось»~~ — на экране проверки установки уже заменяется на «Резервная копия ещё не создавалась»; в других местах формулировка осталась.
- После закрытия меню x-ui остаётся сырой английский вывод.
- При «Подставить логин и пароль» не видно, сработало ли.

### 2.5. Крайний случай смены порта
На systemd 247 `systemctl disable` в шаге `finish` перезагружает менеджер, и таймер `velum-ssh-restore-22` пропадает до удаления файла состояния. Если `finish` упадёт между этими шагами, автоматического возврата порта 22 не будет.

## 3. Что не проверено

- Откат восстановления (возврат прежней базы, запуск после отката).
- Восстановление базы с реальными клиентами и настройками (проверялось только на пустой базе).
- Обновление 3x-ui через приложение.
- Reality Scanner, «Диагностика», «История проверок», журналы, автозапуск, «Узнать версию».
- «Проверить вход в панель», «Сбросить логин и пароль», «Открыть панель в интернет» после закрытия.
- Удаление защиты от сканеров; что после всех функций на сервере не остаётся мусора.
- Создание VLESS на Debian 13; весь сценарий на Debian 11 после смены security-репозитория.
- Вход по паролю с `sudo` (SUDO_PASSWORD) после правки `SESSION_ENV`.
- androidTests, release-сборка, подпись (`VELUM_RELEASE_*`), установка release поверх debug.
- Другие ОС и архитектуры (Ubuntu 22.04/24.04, Debian 12, ARM64).
